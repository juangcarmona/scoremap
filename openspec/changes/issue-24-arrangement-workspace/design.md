# One musical context, independent performed ownership

Song form remains shared. Arrangement, part and physical configuration keep their independent identities. Configuration commands validate complete graphs; deleting a referenced part/device requires a current explicit affected-resource snapshot and confirmation. Removing a binding alone never changes notes. Copying an arrangement remaps only arrangement-owned identities; independent song duplication remaps all copied song-owned identities while retaining external copied-preset provenance.

All consultation views derive active occurrences from the same identified measure and rational event-start coordinate, including performed durations and tied occurrences. Repeats carry an explicit occurrence number without cloning content. Device views collect currently routed events by event identity, retaining distinct parts at the same pitch and avoiding duplicate counting of one event routed through overlapping layers. Silent views recompute from current context and clear previous highlights. Each device keeps a local independent viewport; view controls issue no content commands.

Editable keyboard keys retain at least 48-pixel touch geometry. In landscape consultation the read-only piano diagram may use compact complete keys so multiple keyboards are readable together; its keys are not interactive, while navigation and view controls retain 48-pixel touch targets. Use bounded horizontal scrolling on narrower views, retaining exact pitch labels and explicit indication of played notes outside the visible area. Part/role/optional hand and sound/layer labels explain routing independently of color. Keep all content configuration behind edit admission and private song capability. The existing native/persistent-private-offline qualification gates remain separate.
