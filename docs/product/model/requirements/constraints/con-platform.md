## Constraint

Retain an installable web application for landscape touch tablets, phones and desktop, delivered over protected HTTPS in deployment. Anonymous installed web content supports offline editing/consultation. Authenticated service offline access requires proven protected retention, scoped authorization lease and safe session recovery; persistent private service offline access is disabled for the first connected local checkpoint.

Also provide an installed native Android application for touch tablets and phones. Its personal durable library works without an account, login, network or backend dependency. Native local acknowledgement is authoritative on that installation, not a service save. Native document selection and file sharing transport complete editable song/set files; they do not create a collaborative account service, live synchronization or public share links. Installation is in scope; no app-store publication is implied.

Development and Production are explicit environments, not machine locations. Production refuses development identities/seeds, development serving and ephemeral persistence fallbacks. Public examples and evidence contain synthetic data only; real configuration, credentials, identities, personal music and deployment inventory remain private. Application, site, documentation and evidence origins remain parameterized pending the owner's publication choice.

## Rationale

Maintain the tablet-first web product and honest private recovery while adding standalone native musical work and independent file exchange.

## Consequences

A running development graph or local qualification is not production qualification or deployment. Shell availability does not authorize cached private service content. Native local authority neither claims an authenticated service account nor bypasses service authorization.
