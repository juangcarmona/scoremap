## Goal

Export and reconstruct complete declared musical scope through a documented versioned envelope without loss or imported authority. Preserve existing browser replacement/private claim and add native independent editable song/set copy exchange that never replaces destination music.

## Trigger

The musician requests export, selects a file for import, receives an incoming file, or requests claim of retained anonymous browser work. Export, browser replacement, native independent-copy import, private import and claim are separate interactions.

## Preconditions

The source is readable and retained unchanged until success; existing targets resolve. Private-service reads/exports and destination actions require real authentication/current scoped capabilities; deleted private content requires current-owner fresh online authorization. Native local work requires no login/backend. Mutations require edit admission, complete valid data and expected revisions. Imported owners/grants cannot authorize an action. The destination supports every included version/capability or refuses before activation.

## Main Flow

1. Select the operation and explicit scope. Distinguish anonymous browser complete-library replacement, bounded private import/claim with separately owned resources, and native selected-current-song/complete-ordered-set exchange.
2. For export, check applicable source authority and prepare the complete versioned envelope with identities/order, form, timing/repeats, spelling, exact pitches, arrangements/parts/voicings, hands, musical bindings, memberships, reminders/references and supported attachment bytes. Preserve provenance and explicit resource scope; exclude credentials, sessions/access material and grants. Export does not mutate or acknowledge pending music. Native export excludes device-private history, app preferences and actual hardware configuration/authority while copying musical definitions required for reconstruction and complete owned PDF bytes/integrity references.
3. Validate the entire import graph before activation and preview destination effects, boundaries, supported migrations and identity mappings for confirmation. Anonymous browser replacement explicitly names whole-library replacement; private claim never silently replaces the account library; native import never replaces, overwrites, merges or updates existing destination objects.
4. Private import/claim derives destination ownership from the trusted principal, refuses collisions and offers explicit consistently remapped copy-as-new. Native import always allocates an independent consistent graph-wide mapping, even if no source collision appears. Preserve ordered membership and shared dependencies, copy required reusable musical definitions and start independent destination history.
5. On confirmation recheck applicable authorization, edit admission, revision and complete validity. Acknowledge private declared complete boundaries with principal-bound receipts, and separately owned resource receipts; report exact multi-boundary progress. Native import instead acknowledges the entire selected song/set graph atomically, with mapping, initial histories, command receipt and qualified required-attachment publication. No partial acknowledged native set is allowed.
6. Reconstruct and present the actual result. For claimed private content, verify authorized remote reconstruction before offering separate explicit source removal; retain the anonymous source until then. For native file exchange preserve the original input and source music; same-command reconciliation reuses its result, while a deliberately new import may create another independent copy. No transaction is claimed across source/destination installations, service or share transport.

## Alternative Flows

- A supported empty anonymous browser backup remains valid confirmed complete replacement and yields EMPTY; nonempty replacement yields POPULATED. Existing IMPORT-EMPTY/IMPORT-POPULATED commands retain their browser scope; native import cannot use an empty file to clear existing music.
- Supported browser v1 migration preserves existing identities, order, repeats and triad spelling, applies BR-STRUCTURE's timing/default-arrangement rules without invented performed notes, retains a recovery copy and deterministic generated-ID receipt reused on retry.
- Cancelling preview leaves source/destination unchanged. Declining private copy-as-new never overwrites a collision.
- A committed command with lost response reconciles its original context-bound receipt before repeating a write; no duplicate song/revision/import copy results.
- A new browser origin requires explicit export from the old origin and cannot read its storage. Native document exchange is an explicit separate transfer, not automatic origin/device migration or live synchronization.
- Operator backup restoration remains distinct and reconciles current authorization and deletion/purge receipts before access. Stale restore/replay cannot resurrect a purged identity. A deliberate independent copy is a different identity, not purge reversal.
- Repeatable private journeys use the same selected synthetic identity fixture/configuration as manual real-login trials, with execution-scoped reset, no mocked authority or existing-library reset and no Production development defaults.
- Native external links stay explicit links; source-local paths cannot substitute for owned PDF bytes. Unavailable messaging/email routes are reported honestly rather than inferred from successful file generation.

## Failure Conditions

Malformed/truncated/oversized input, duplicates, dangling associations, invalid values/timing/pitches, incomplete graphs/attachments, unknown versions/capabilities and failed migrations refuse before activation, preserving original source and last durable destination. Never silently strip unsupported declared content. Existing browser/service attachment capability remains conditional on support; native complete PDF transfer is required for native acceptance.

Performance mode refuses import/claim. Missing applicable service authority, forged owners/grants, unknown targets, stale revisions and identity conflicts cannot grant access or overwrite content. Failed declared transactions preserve prior complete boundaries. Ambiguous responses reconcile receipts, not assumed rollback. Service multi-boundary failure identifies completed receipts and remaining work. Native storage/attachment-publication failure admits no partial selected graph or broken attachment and leaves previous music intact.

Private session expiry, unknown authority and observed revocation lock service-owned work and stop export/replay. Retained service drafts remain protected for same-principal online permission/revision checks and explicit reconciliation; retained records/cached roles are not authority. Native local operation does not bypass that protection. Refused commands make no lifecycle transition.

## Postconditions

Complete authorized scope is exported or durably reconstructed under the chosen policy, or source and previous acknowledgement remain preserved with an actionable reason. Native results are independently editable copies with all existing destination music unchanged; private claim remains non-destructive until verified recovery and separate source-removal choice. No imported authority, silent merge, hidden ownership assignment, instant erasure or remote-save claim follows from local exchange.
