# Independent personal-resource checkpoint

The candidate protects original notation, reusable-voicing and device-configuration commands before transport. Independent journal slots bind principal, editing context, kind and resource; AES-GCM authenticates that slot. A matched content/revision acknowledgement removes the confirmed command. Explicit review, original-command retry, comparison export and removal preserve ambiguous work across closing, restart and account switching. A failed personal protection operation does not prevent a separately valid song commit; termination still reports that protection failure.

Personal recovery uses a separate server key purpose. Older keys receive the `song` default and keep their original protection context. Wrong-principal and opposite-purpose unlocks refuse, a personal key cannot bind a song commit, and revoking a song grant does not remove ownership of independent personal resources. Explicit server-key deletion prevents later unlock.

Reusable physical-device configurations have independent principal ownership, revisions, conditional commits and retry receipts. Anonymous configurations use a separate atomic local store. Applying a configuration copies its content to a new song-owned device identity without changing parts, bindings, performed notes, shared form or another arrangement. Later resource edits/deletion do not change that copied device. The separate version-1 single-configuration export/import format validates completely and creates an explicitly confirmed independent resource copy; source files and other resources remain intact.
